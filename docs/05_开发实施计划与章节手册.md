# Personal Daily OS — 开发实施计划与章节手册 V1.0

> 日期：2026-08-17  
> 项目：Personal Daily OS  
> 目标：将 PRD、页面架构、数据库 Schema 与 UI 规范转化为可由 Codex 按章节连续执行的开发计划。

---

# 1. 开发总原则

本项目采用：

> **按章节开发 → 每章自测 → 通过验收 → 再进入下一章**

禁止：

- 一次性同时开发全部模块
- 一边开发一边随意更换技术栈
- 未完成基础数据层就提前堆 AI
- 为未来商业化提前设计多用户 SaaS
- 为了视觉效果牺牲真实数据记录
- 大范围重构已通过验收的模块

核心技术路线固定：

```text
Next.js App Router
React
TypeScript strict
Tailwind CSS
shadcn/ui + Radix
React Hook Form
Zod
Supabase PostgreSQL
Supabase Private Storage
Custom PIN Session
IndexedDB + Dexie
Recharts
date-fns
Vercel
GitHub
```

---

# 2. 开发完成定义

一个章节只有同时满足以下条件才算完成：

1. 页面可正常访问。
2. 数据可真实写入数据库。
3. 刷新页面后数据仍然存在。
4. 手机布局无明显溢出。
5. TypeScript 无错误。
6. ESLint 无阻断错误。
7. 核心交互可以完成。
8. 错误状态有反馈。
9. 不破坏已完成模块。
10. 关键业务至少有基础测试。

# 51. 开发阶段最高优先级

永远按以下顺序判断：

```text
1. 数据是否真实保存
2. 是否容易记录
3. 历史是否正确
4. 手机是否好用
5. 是否稳定
6. 是否好看
7. 是否高级
```

如果“高级视觉”和“记录效率”冲突：

> 优先记录效率。

如果“快速开发”和“历史数据正确性”冲突：

> 优先历史数据正确性。

如果“未来扩展”和“当前简单可用”冲突：

> 优先当前简单可用。

# 52. V1 交付标准

最终 V1 应做到：

> 早晨打开 App，可以记录睡眠、体重、有氧和早餐。

> 工作中可以快速记录上午/下午产出。

> 每一顿饭都可以记录 kcal、Protein、Carbs、Fat、Fiber。

> 每一次饮水和支出可以数秒完成。

> 晚上打开训练，可以按照 Push / Pull / Legs / Core 完整记录每一组。

> 训练历史能显示上一次真实重量。

> 晚上完成 Daily Review。

> 第二天进入新的 Today。

> 一个月以后仍然能打开任意一天查看完整记录。

> Insights 能看到身体、饮食、训练、生活和支出趋势。

> 所有已同步数据不会因为刷新、换设备或重新部署而消失。

这就是 Personal Daily OS V1 的开发完成定义。
