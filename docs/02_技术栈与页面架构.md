# Personal Daily OS — 技术栈与页面架构 V1.0

> 日期：2026-08-17  
> 项目定位：单用户、自用、手机优先、云端长期存储的个人生活工作台 PWA

---

## 1. 技术目标

本项目第一阶段不追求商业 SaaS 架构，也不做多用户、注册、社交和复杂权限系统。

核心要求：

1. **手机端体验优先**：可以安装到手机桌面，接近 App 使用体验。
2. **数据长期保存**：换手机、清缓存、重新部署都不能丢历史数据。
3. **操作足够快**：饮水、记账、训练组、饮食等高频操作尽量 1～3 次点击完成。
4. **隐私可控**：公网部署，但需要 PIN 解锁，数据库和图片不能公开暴露。
5. **方便未来接 AI**：当前先记录真实结构化数据，后续再做 AI 食物识别、训练建议、每日总结等。

# 4. PIN 与单用户安全架构

当前产品只有本人使用，因此 V1 不做：注册、邮箱验证、OAuth、找回密码、多用户和租户系统。

访问流程：

```text
打开 App
  ↓
检查 Session
  ↓
未解锁
  ↓
输入私人 PIN
  ↓
服务器验证 PIN Hash
  ↓
写入 HttpOnly Session Cookie
  ↓
进入 App
```

PIN 不明文保存，服务端只保存 Argon2id 等安全 Hash。Session 推荐使用 HttpOnly、Secure、SameSite=Lax，并支持自动失效。

首次部署使用环境变量保护初始化：

```env
APP_SETUP_SECRET=
APP_SESSION_SECRET=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

首次进入 `/setup` 必须同时提供 Setup Secret 和新 PIN；完成后写入 `setup_completed=true` 并关闭初始化入口。

# 5. 数据访问与 Supabase 安全

推荐所有私人读写统一走：

```text
Client
  ↓
/api/*
  ↓
Next.js Server
  ↓
Supabase
```

示例 API：

```text
GET    /api/today
POST   /api/meals
PATCH  /api/meals/:id
DELETE /api/meals/:id
POST   /api/water
POST   /api/expenses
POST   /api/workouts/start
POST   /api/workouts/:id/set
POST   /api/workouts/:id/finish
GET    /api/history/:date
GET    /api/insights/*
```

每个私人 API 统一执行 `requireUnlockedSession()`，失败返回 401。

Supabase 建议：

- 业务表全部启用 RLS。
- 不创建 anon / authenticated 的公开访问 Policy。
- 浏览器不直接操作数据库。
- 服务端使用 service role。
- Storage Bucket 设为 Private。
- 图片读取使用短时 Signed URL。

# 6. Offline / 弱网策略

V1 不做复杂双向同步，采用简单 Outbox：

```text
用户创建记录
   ↓
网络正常 → 直接写服务器 → 更新本地缓存
   ↓
网络断开 → 写入 IndexedDB Outbox
   ↓
显示“待同步”
   ↓
网络恢复 → 顺序重放请求 → 服务端幂等写入
```

IndexedDB 建议表：

```text
cached_today
local_drafts
sync_outbox
sync_metadata
```

优先支持离线：饮水、支出、晨重、随手记、工作记录、Workout Set。图片 V1 可以要求联网后上传。

为避免弱网重试产生重复记录，高频写入支持 `client_idempotency_key`。

# 7. 历史快照原则

## 7.1 食品

`food_library` 是当前食品模板；真正吃掉时，`meal_items` 保存当时的名称、重量和营养快照。

这样以后修改蛋白粉或鸡胸肉营养信息，不会改变几个月前的真实饮食记录。

## 7.2 训练

`workout_plans` 是当前计划；开始一次训练时，将动作名称、目标组数、次数范围、休息时间等复制到 `workout_session_exercises`。

未来从 V1 改成 V2，不改变历史训练。

# 20. UI 视觉基线

- 白色主背景
- 蓝色单一主强调色
- 不使用大面积蓝紫渐变
- 大圆角
- 低对比边框
- 轻阴影
- 信息密度中高
- 数字和进度信息优先可读
- 手机端触控区域足够大

避免：黑暗赛博风、企业后台感、过度渐变、过多玻璃拟态、装饰性动画过多、每件事都弹完整表单。
